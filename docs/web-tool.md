# Web Testing Tool

The web testing tool is a browser-based debugging environment for ONNX combat policies. It can run a combat simulation, load a policy model, inspect observations, visualise rewards and monitor action probabilities.

It is contract-compatible, but it is not an authoritative replacement for the
Python/Unreal parity tests. Browser physics, combat and rewards remain a
lightweight approximation.

## Setup

```bash
npm install react react-dom d3 onnxruntime-web
npm install -D @types/d3 typescript
npm run dev:local
```

The tool can run with a scripted fallback AI, so a model is not required for basic UI testing.

## Controls

| Key/Input | Effect |
|---|---|
| WASD | Move player |
| Click canvas | Shoot toward cursor |
| Space | Shoot at AI agent |
| R | Reload |
| Enter | Restart after game over |

## ONNX Model Loading

Upload an ONNX model through the header bar. Current policy exports use:

```text
observation input: [batch, 747]
hidden_in input:   [1, batch, gru_hidden]
movement_logits:   [batch, 9]
combat_logits:     [batch, 9]
target_logits:     [batch, 5]
hidden_out:        [1, batch, gru_hidden]
```

The web tool should stay aligned with the Python/C++ model constants:

```text
OBS_SIZE = 249
FRAME_STACK = 3
INPUT_DIM = 747
MOVEMENT_ACTIONS = 9
COMBAT_ACTIONS = 9
TARGET_ACTIONS = 5
```

The movement, combat and target logits are independent heads produced in one
inference call. Model loading requires the exact named inputs/outputs above,
validates the 747 input and 9/9/5 head widths, carries `hidden_out` into the
next decision, and clears hidden state when an episode resets.

## Actions

```text
Movement: hold + 8 compass directions
Combat:   none, fire, reload, switch0, switch1, melee, block, dodge, reposition
Target:   scored hostile slots 0..3 + keep current
```

Dodge is only triggered by combat action 7; the sandbox has no automatic
dodge path. Reposition is combat action 8 and uses the independently selected
movement direction for 0.6 seconds at 1.75x speed, with a 3.0-second cooldown,
normal collision and no invulnerability. Reposition plus Hold is a true no-op
and does not consume the cooldown.

## Difficulty Tiers

The active profiles are `Micro`, `Small`, `Medium` and `Large`. `XL` is not an
active tier. All use the same 249 x 3 tensor contract, so an uploaded model's
tier cannot be inferred from its shape; select the intended tier explicitly.

## Components

### Reward Chart

Shows instant or cumulative reward. Useful for spotting reward farming or reward spikes that do not correspond to meaningful combat progress.

### Action Probability Heatmap

Displays movement, combat and target-head probabilities. Useful for checking entropy, invalid-action masking and head collapse.

### Reward Budget Bar

Compares actual cumulative reward against expected win/loss/timeout budgets. Useful for detecting episodes where shaping rewards outscore objectives.

### Batch Episode Runner

Runs multiple headless episodes and reports aggregate win rate, reward, kills and warning flags.

### Observation Inspector

Displays the 249 observation features grouped by category, with change highlighting. Useful for finding all-zero groups, wrong offsets or unexpected jumps.

The browser builder uses the production offsets. Features unsupported by this
lightweight simulation are deliberately zero rather than fabricated:

- primary/hostile character type, mana, commitment and gap-closer fields
- all three allied-robot slots
- the five player-pattern EMA fields

That makes dimensional/model-I/O testing honest, but observations generated by
this tool must not be used as proof of full environment parity or as training
data for production policies.

## Keeping In Sync

When these change in Python or C++, update the web tool as well:

- observation layout and `OBS_SIZE`
- frame stack/input dimension
- action labels and action counts
- reward weights used for visualisation
- weapon presets and projectile/arc rules
- ONNX input/output names, especially `hidden_in` and `hidden_out`
